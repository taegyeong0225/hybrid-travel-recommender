# 9주차: 백엔드 추천 API 성능 개선 및 자동 갱신 기능 구현

## 1. 목표

기존 FastAPI 백엔드에서 매번 호출 시마다 추천 모델을 재실행하여 응답 속도가 느렸던 `/recommend` 엔드포인트의 성능을 개선한다. Redis를 이용한 캐싱을 도입하고, 특정 조건(날짜, 날씨) 변경 시 캐시가 자동으로 갱신되도록 구현한다.

## 2. 주요 변경 사항

### 가. Redis 캐싱 도입

- **목적**: 반복적인 모델 실행을 방지하여 API 응답 속도를 향상시키고 서버 부하를 줄입니다.
- **구현**: 
    - 사용자의 추천 결과를 Redis에 저장하는 캐싱 로직을 `backend/app/main.py`에 추가했습니다.
    - 캐시 키는 `recommend:{user_id}` 형식을 사용합니다.
    - 캐시의 유효 시간(TTL)은 **30분**으로 설정하여, 주기적으로 데이터가 갱신될 수 있도록 했습니다.

### 나. 자동 캐시 무효화 (Cache Invalidation)

- **목적**: 항상 최신 컨텍스트(날짜, 날씨)에 맞는 추천을 제공하기 위해, 특정 조건 충족 시 기존 캐시를 자동으로 파기하고 새로운 결과를 생성합니다.
- **구현**:
    1.  **날짜 변경**: API 호출 시점의 날짜가 캐시에 저장된 날짜와 다를 경우 (예: 자정이 지난 경우) 캐시를 무효화합니다.
    2.  **날씨 변경**: 서울 지역의 현재 날씨 상태(맑음, 비 등)가 캐시에 저장된 날씨와 다를 경우 캐시를 무효화합니다.

### 다. 백엔드 아키텍처 개선

- **문제점**: 기존에는 `subprocess`를 통해 Python 스크립트를 실행하여 추천 결과를 받아오는 비효율적인 구조였습니다.
- **개선**: FastAPI 애플리케이션이 시작될 때(`on startup`) 추천 모델을 미리 메모리에 로드하는 방식으로 변경했습니다. 이를 통해 모델을 한 번만 로딩하고, 이후 요청에서는 로드된 모델을 즉시 사용하여 응답 속도를 크게 개선했습니다.

### 라. 환경 변수 관리

- **목적**: 민감한 정보(API 키)를 코드나 `docker-compose.yml` 파일에서 분리하여 보안을 강화합니다.
- **구현**: 
    - 날씨 API 호출에 필요한 `OPENWEATHER_API_KEY`를 환경 변수로 관리하도록 변경했습니다.
    - `backend/.env.docker` 파일을 새로 생성하여 데이터베이스 정보와 API 키를 관리하도록 구성했습니다.

## 3. 파일 변경 내역

- **`backend/app/main.py`**: 
    - Redis 연결 및 캐싱 로직 전체를 구현했습니다.
    - 애플리케이션 시작 시 모델을 로드하도록 수정했습니다.
    - 기존 `subprocess` 호출 코드를 제거하고, 직접 `recommender.recommend()`를 호출하도록 변경했습니다.
- **`backend/app/schemas.py`**: 
    - 추천 API의 응답 규격을 정의하기 위해 `RecommendationResponse`, `RecommendationItem` 등 Pydantic 모델을 추가했습니다.
- **`backend/.env.docker` (신규 생성)**:
    - `OPENWEATHER_API_KEY`와 데이터베이스 연결 정보를 추가했습니다.

## 4. 기대 효과

- **응답 속도 향상**: 캐시 `HIT` 시, 모델 재실행 없이 저장된 결과를 즉시 반환하여 API 응답 시간이 대폭 단축됩니다.
- **서버 부하 감소**: 불필요한 CPU 및 메모리 사용을 줄여 더 안정적인 서비스 운영이 가능해집니다.
- **동적인 추천**: 날씨나 날짜 등 외부 요인이 변경될 때마다 자동으로 새로운 추천을 제공하여 사용자에게 시의성 있는 정보를 전달할 수 있습니다.
